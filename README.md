# PatternMystery

1~3인 온라인 협동 공포 미스터리 어드벤처의 Godot 4 프로토타입입니다.

현재 저장소에는 프로젝트가 열리고 최소 화면을 표시하기 위한 셸만 있습니다. CH1 게임 로직과 콘텐츠는 아직 구현하지 않았습니다.

## 이번 단계의 범위

- Godot 4 프로젝트 셸
- Placeholder 시작 화면
- CH1 Vertical Slice 아키텍처 결정
- 구현 순서 기록

다음 기능은 범위 밖입니다.

- 완성형 CH1
- 계정, 매치메이킹, 데이터베이스
- AI/LLM
- 자체 음성채팅
- 공용 저널 및 저널 공유
- 저장/불러오기 완성본
- 최종 아트

## 기본 아키텍처

처음부터 범용 게임 엔진을 만들지 않습니다. CH1 Vertical Slice에 필요한 상태와 Guard를 명시적으로 구현하고, CH2에서도 반복되는 구조만 나중에 공통화합니다.

### 권한

Host가 authoritative server 역할을 합니다.

- 클라이언트는 `이동`, `조사`, `응답`, `동행` 같은 의도만 전송합니다.
- Host가 현재 상태와 Guard를 검증합니다.
- Host만 World State와 Pattern State를 변경합니다.
- 클라이언트에는 그 플레이어가 볼 수 있는 결과만 보냅니다.
- 장기적으로 Host 로직을 headless dedicated server로 옮겨도 같은 권한 경계를 유지합니다.

### 상태 경계

첫 Vertical Slice에서는 아래 네 덩어리만 둡니다. 구현 전부터 세부 클래스 계층을 만들지 않습니다.

- `world`: 방송 전원, 회선, 작업자 흔적, 한 번만 발생하는 사건
- `players`: peer ID, 위치, Designation, 개인 저널
- `locations`: 장소별 오브젝트와 변경 상태
- `pattern`: SLOT_8/21, 호출, 응답, 이동 대기, 단독 분리 여부

`phase`는 원인이 아닙니다. 필요하면 디버그 화면에서 현재 진행을 요약하는 값으로만 계산합니다.

### 플레이어별 View

전체 상태를 클라이언트에 복제하지 않습니다. Host는 각 peer에 대해 다음만 구성합니다.

- 현재 장소와 상호작용 가능한 오브젝트
- 그 장소에서 감지할 수 있는 사건
- 해당 플레이어의 자료/목격 저널
- 공개 가능한 다른 플레이어의 위치와 큰 상태

숨은 Guard, 다른 플레이어의 개인 사건, 미발견 문서 원문은 보내지 않습니다.

### 개인 저널

저널 항목은 원문을 중복 저장하기보다 콘텐츠 ID와 발견 메타데이터를 가집니다.

- `entry_id`
- `kind`: `material` 또는 `witness`
- `location_id`
- `discovered_order`
- `discovered_by`

Host가 플레이어별 열람 권한을 보유하고, 클라이언트는 허용된 항목의 원문만 받습니다. 공유 여부는 Guard나 진행 조건으로 사용하지 않습니다.

### Pattern 처리

범용 규칙 언어나 그래프 편집기를 만들지 않습니다. 각 행동은 Host의 한 진입점에서 처리하고, CH1 Guard를 명시적으로 검사합니다.

예를 들어 21번 호출은 다음과 같은 실제 조건이 모두 맞을 때만 발생합니다.

- 필요한 선행 행동이 관찰됨
- 방송 Carrier 사용 가능
- SLOT_21이 비어 있음
- 대상이 아직 다른 슬롯에 고정되지 않음
- 관련 회선에서 호출 가능

Transition은 한 번만 적용되고 사건 ID를 기록합니다. 같은 요청이 중복 도착해도 결과가 두 번 발생하지 않게 합니다.

## CH1 Vertical Slice 구현 순서

1. 한 클라이언트에서 네 장소 이동과 Placeholder UI를 구현합니다.
2. 이동·조사 행동을 하나의 authoritative action 처리 경로로 모읍니다.
3. 자료와 목격을 개인 저널에 등록하고 다시 열람하게 합니다.
4. Godot의 `ENetMultiplayerPeer`로 Host 1명과 Client 2명을 localhost에 연결합니다.
5. 플레이어 위치를 Host가 관리하고 각 클라이언트에 자기 장소 View만 보냅니다.
6. 안전 방송과 실제 위험 상태를 연결합니다.
7. 작업자의 SLOT_8 흔적과 2003년 기록 일부를 배치합니다.
8. 명시적인 Guard로 한 플레이어를 SLOT_21에 고정하고 개인 호출을 보냅니다.
9. 호출 응답 후 Pattern을 `이동 대기` 상태에 멈춥니다.
10. 방송실의 다른 플레이어에게 회선 `WAITING` 변화를 보냅니다.
11. 이동과 동행을 처리하고 단독 분리 Guard 실패를 검증합니다.
12. 세 창을 동시에 실행해 전체 흐름과 정보 누출을 테스트합니다.

각 단계는 앞 단계가 실제로 실행된 뒤에만 진행합니다.

## 가장 큰 기술적 위험

1. **개인 정보 누출**: 전체 World State를 클라이언트에 보내면 숨은 진상과 다른 플레이어의 사건이 노출됩니다.
2. **동시 행동 순서**: 응답과 전원 차단처럼 거의 동시에 도착한 행동은 Host에서 순서대로 검증·적용해야 합니다.
3. **재접속 복원**: 현재 상태와 과거에 직접 본 사건을 구분하지 않으면 재접속 시 정보를 잃거나 보지 않은 정보를 받게 됩니다.

## 다음 작업

Godot 실행 확인 후 가장 먼저 한 클라이언트용 네 장소 이동과 개인 저널을 구현합니다. 네트워크를 붙이기 전에 동일한 action 처리 경로가 로컬에서도 Host 권한으로 동작하게 만듭니다.
